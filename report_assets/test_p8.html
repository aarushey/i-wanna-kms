8. Stored Procedures & Explicit Cursors

Stored procedures are pre-compiled SQL modules stored directly within the database catalog. When business logic demands row-by-row procedural traversal over a set of tuples rather than set-oriented operations, PL/SQL Cursors provide explicit pointer navigation.

Stored Procedure Definition: sp_check_availability

DELIMITER // CREATE PROCEDURE sp_check_availability( IN p_venue_id INT, IN p_date DATE, OUT p_is_available BOOLEAN ) BEGIN DECLARE done INT DEFAULT FALSE; DECLARE b_date DATE; DECLARE cur CURSOR FOR SELECT booking_date FROM bookings WHERE venue_id = p_venue_id AND status = 'CONFIRMED'; DECLARE CONTINUE HANDLER FOR NOT FOUND SET done = TRUE; SET p_is_available = TRUE; OPEN cur; read_loop: LOOP FETCH cur INTO b_date; IF done THEN LEAVE read_loop; END IF; IF b_date = p_date THEN SET p_is_available = FALSE; LEAVE read_loop; END IF; END LOOP; CLOSE cur; END // DELIMITER ;

Cursor Execution Lifecycle

  1. Declaration: Defines the select query and establishes pointer workspace.
  2. Continue Handler: Traps the NOT FOUND state, gracefully toggling loop termination.
  3. Open & Fetch: Allocates cursor memory buffers and sequentially steps through active dates.
  4. Early Exit Optimization: Breaks the loop immediately when a date match is detected, conserving CPU cycles.
  5. Close: Explicitly deallocates memory buffers, avoiding database cursor leaks.
