6. Advanced RDBMS: Automated PL/SQL Triggers

In relational database design, triggers represent active rules that execute automatically in response to specific Data Manipulation Language (DML) events (INSERT, UPDATE, DELETE). UniBook utilizes triggers to maintain real-time denormalized summary statistics without placing the burden of synchronization on application-level queries.

Trigger Definition: After_Booking_Insert

The trigger After_Booking_Insert automatically increments the lifetime reservation counter total_bookings in the venues table whenever a new booking is inserted into the bookings table:

USE unibook_db; DROP TRIGGER IF EXISTS After_Booking_Insert; DELIMITER // CREATE TRIGGER After_Booking_Insert AFTER INSERT ON bookings FOR EACH ROW BEGIN UPDATE venues SET total_bookings = total_bookings + 1 WHERE venue_id = NEW.venue_id; END // DELIMITER ;

Architectural & Performance Justification

Calculating the popularity or lifetime usage of venues by repeatedly executing aggregate queries (SELECT COUNT(*) FROM bookings WHERE venue_id = ?) incurs a high computational cost on high-traffic dashboards, requiring repeated B-Tree index scans. By delegating counter increments to an AFTER INSERT database trigger:

  • Transactional Atomicity: The counter update executes within the same atomic transaction scope as the booking insertion. If the booking transaction rolls back, the counter modification is discarded.
  • Zero Application Overhead: Any client inserting a row (REST API, batch ETL script, direct SQL terminal) automatically updates the counter without writing redundant application logic.
